| Pclp for small on-screen parts | Pre-clipping costs up to 5 clocks a fill line. For parts wholly on the screen (hex tiles, seams, HUD) setting Pclp (CMDPMOD bit 11) saves it. Needs VDP1 version 1 (MODR bits 15-12; check on the Saturn; Mednafen may not model the saving) | S |
| HSS for far wall textures | High-speed shrink (CMDPMOD bit 12) samples only even (or odd) texels when a texture is shrunk: faster, and the same texels every time. That may also steady "Far-wall texture LOD" (rows dropped differently by neighbours). VDP1 version 1 only | S |
| Glass that you see through, cheaply | VDP1 half-transparency is 6x the pixel cost and uneven on polygons (diagonal lines write pixels twice). Two cheaper ways: mesh (CMDPMOD bit 8, a checkerboard screen door with no frame-buffer read; on a CRT it reads as see-through), or VDP2 colour calculation of the whole VDP1 layer over the VDP2 layers (free, but it's one ratio for all RGB polygons, register 0, and it blends only with VDP2 under it, not VDP1 with VDP1). For the art direction's glass | M |
| The doorway as a VDP2 window | A line window (a start and end x per screen line, a VRAM table) can make a VDP2 layer show only through a shape. When the far city goes on VDP2 (Culling plan), show it only through the doorway from inside the corridor, at no VDP1 cost | M |
| Free juice: colour offset and the back screen | Colour offset adds a signed value to R, G, B per layer, after blending: a crash flash, a reset fade or tear, a boost flash, with no drawing at all (the "Crash juice" and "A reset effect" rows). The back screen can be one colour per line: a sky gradient for nothing | S |
| The seams' polylines draw each edge twice | A polyline (a, b, c, b) draws four lines for two edges: twice the seam pixels. Two line commands draw half the pixels for one more command. Measure which is cheaper (seams were part of the floor's cost) | S |
| `glass_anchor` draws one pixel | A quad with four equal corners draws one pixel (black), not nothing. The floor drawn after it covers it. If a lone black dot ever shows at the far glass's deepest corner, that's the cause | S |
| The floor fog's DMA vs the SCU precautions | `floor_fade_vdp2.c` rewrites the ratio every row by SCU DMA level 0 on HBlank. The SCU's final precautions add three risks only the Saturn shows. (12) CPU writes to the B-bus come first: while the CPU or SGL writes non-stop to a VDP (command lists, the Gouraud tables), the row's DMA waits, so that row's ratio lands late (a fog row a line out). (23) **Fixed 2026-11-05, uncommitted:** a level's mode (D0MD) and address steps (D0AD) rewritten while it transfers hangs the Saturn; `arm_dma` cleared the enable a moment before writing them, which doesn't stop a transfer in flight, and the status register that would say so was deleted (13). Now `stop_dma` clears the enable and waits for the row counter to move on twice (a whole line: a transfer ends within its line, 22) before anything's written: ~1.5 lines a frame, in VBlank. The fog looks the same in Mednafen; only the Saturn can show the hang is gone. Still open: (20) SGL uses levels 1 and 2 (its transfers, PCM sound); with ours, 3 at once, the priority order isn't guaranteed. Watch for fog rows that jitter while sound plays or the scene is busy (HARDWARE_TESTS 1) | S |
| The heap's second zone is Work RAM-L | `jo_add_memory_zone` (main.c) gives jo_malloc Low Work RAM once the high zone is full. SCU DMA can't read it (precaution 4). Today nothing DMA'd comes from the heap, but as the heap grows, anything that will be DMA'd (to VDP1/VDP2, or by SGL's level 1) must be taken from the high zone: a check or a separate allocator for "DMA-able" buffers | S |
| A VDP1 timer from the sprite draw end interrupt | The gauge says *whether* VDP1 outlasted the CPU. VDP1's sprite draw end interrupt (SCU vector 0x4D) marks the moment it finishes: an FRC reading there gives VDP1's own time as % of a frame, next to `cpu`. Check SGL's use of that interrupt first | S |
| The SCU DSP for transforms (maybe) | A third processor nothing uses yet: 32x32 multiply, 48-bit accumulate, its own DMA, half the CPU clock. Some games ran their matrix x vertex work on it. Only worth it if the CPU becomes the limit on foot (today it's VDP1 in the slow views) | L |
| Raster effects with SCU Timer 0 | Timer 0 interrupts at any chosen screen line (0..263 in NTSC): a split screen for 2 players, the horizon line, a heat-haze band, without the per-row DMA. Note SGL rewrites the SCU interrupt mask (SKILLS) | M |

## Next: floor pixelation (proposed 2026-10-27)

The floor is VDP2's rotating background (RBG0): a 64x64, 8-bit FLOOR.TGA tiled every 64 world units,
1 texel per unit, no filtering. Near the low 1st person camera each texel is a big block; far away
